Sub-agents: Specialist Workers যারা আসল কাজ করে

Gateway request নেয়। Orchestrator plan করে। Memory context দেয়। কিন্তু আসল কাজ করে কে? Sub-agents। এরা হলো specialist। প্রতিটা একটা নির্দিষ্ট কাজে expert। এই post-এ দেখবো agent কীভাবে design করতে হয়, prompt কেমন হওয়া উচিত, আর কীভাবে tool registry-র সাথে কথা বলে।

একটা hospital-এর কথা ভাবো। General physician আছে। কিন্তু brain surgery দরকার হলে neurosurgeon লাগে। Heart-এ সমস্যা হলে cardiologist। Generalist দিয়ে সব কিছু হয় না। Sub-agents ঠিক এভাবে specialize করা।

একটা general-purpose agent দিয়ে সব কাজ করানো technically possible। কিন্তু production-এ এটা কাজ করে না। কারণ prompt বড় হয়, context confused হয়, আর output quality পড়ে যায়। Specialist agent-রা smaller, faster, আর তাদের domain-এ অনেক ভালো।

"Do one thing and do it well." Unix philosophy। Sub-agent design-এও exactly এটা। Research agent শুধু research করে। Code agent শুধু code। কেউ কারো কাজে interfere করে না।
চারটা Core Agent: কে কী করে
Research agent
খোঁজে, পড়ে, summarize করে
Input: query string, search scope
Tools: arXiv, Semantic Scholar, web search
Output: ranked papers with summaries
Context window: 16k tokens
Model: claude-haiku (speed priority)
Code agent
লেখে, চালায়, debug করে
Input: task spec, relevant codebase
Tools: code executor, file system, terminal
Output: working code + test results
Context window: 32k tokens
Model: claude-sonnet (quality priority)
Analysis agent
data দেখে, pattern বের করে
Input: structured data, analysis goal
Tools: code executor, DB query, charting
Output: insights, charts, conclusions
Context window: 32k tokens
Model: claude-sonnet (reasoning priority)
Synthesis agent
সব output জোড়া দেয়
Input: all previous agent outputs
Tools: file writer, formatter
Output: final coherent document
Context window: 100k tokens
Model: claude-sonnet (coherence priority)
পুরো Flow: Agent কীভাবে কাজ করে

Orchestrator একটা task dispatch করে। Agent সেটা পায়। তারপর একটা loop চলে: think, act, observe। এই loop-ই agent-কে agentic করে তোলে। শুধু একবার LLM call না, বরং tool call করে, result দেখে, আবার decide করে।

Prompt Anatomy: Agent-এর System Prompt কেমন হওয়া উচিত

Agent-এর quality সবচেয়ে বেশি depend করে তার system prompt-এ। চারটা section থাকা উচিত। প্রতিটার আলাদা কাজ। একটা বাদ দিলে agent confused হয়।

System identity
You are a research agent specializing in ML paper discovery and summarization. Your job is to find relevant papers, extract key claims, and return structured summaries. You are not a general assistant. Do not answer questions outside your scope. If a task is not about paper research, say so and stop.
Memory context (injected per request)
Previous searches on this topic:
Run digest-a3f9k2 (3 days ago): "PRM generalization" returned 5 papers. Top result: "Let's Reinforce Step by Step": PRM beats ORM on complex reasoning. Gap noted: no cross-domain evaluation at 1B-3B scale.
Current task (from orchestrator)
Search for papers on: "GRPO variants: DAPO and Dr. GRPO training stability"
Max papers: 8. Focus on: training dynamics, reward shaping, small model performance. Avoid: papers already seen in digest-a3f9k2.
Output format
Return JSON with this exact shape:
{"papers": [{"title": "...", "claim": "...", "method": "...", "relevance": "..."}], "gap_identified": "...", "suggested_next_query": "..."}
No markdown. No preamble. Valid JSON only.

agents/base.py · Base agent with ReAct loop 
# agents/base.py
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from anthropic import Anthropic
import json, logging

log = logging.getLogger("agent")
client = Anthropic()

@dataclass
class AgentResult:
    output:     dict
    status:     str          # "done" / "partial" / "failed"
    steps_used: int = 0
    tokens_used: int = 0
    error:      str = None

class BaseAgent(ABC):
    name:       str
    model:      str = "claude-haiku-4-5"
    max_steps:  int = 10
    max_tokens: int = 4096

    @abstractmethod
    def system_prompt(self) -> str:
        """Define agent identity and output format."""
        ...

    @abstractmethod
    def tools(self) -> list[dict]:
        """Tools this agent can use (Anthropic tool_use format)."""
        ...

    async def run(self, task: str, memory_context: str = "") -> AgentResult:
        """ReAct loop: think → act → observe until done."""

        messages = [{
            "role": "user",
            "content": self._build_task_prompt(task, memory_context)
        }]

        steps = 0
        total_tokens = 0

        while steps < self.max_steps:
            steps += 1
            log.info(f"{self.name} step {steps}/{self.max_steps}")

            response = client.messages.create(
                model=self.model,
                max_tokens=self.max_tokens,
                system=self.system_prompt(),
                tools=self.tools(),
                messages=messages,
            )
            total_tokens += response.usage.input_tokens + response.usage.output_tokens

            # agent is done, no tool call
            if response.stop_reason == "end_turn":
                text = response.content[0].text
                try:
                    output = json.loads(text)
                    return AgentResult(
                        output=output, status="done",
                        steps_used=steps, tokens_used=total_tokens
                    )
                except json.JSONDecodeError:
                    return AgentResult(
                        output={"raw": text}, status="partial",
                        steps_used=steps, tokens_used=total_tokens,
                        error="output not valid JSON"
                    )

            # agent wants to call a tool
            if response.stop_reason == "tool_use":
                messages.append({"role": "assistant", "content": response.content})
                tool_results = []

                for block in response.content:
                    if block.type == "tool_use":
                        result = await self._call_tool(block.name, block.input)
                        tool_results.append({
                            "type": "tool_result",
                            "tool_use_id": block.id,
                            "content": json.dumps(result),
                        })

                messages.append({"role": "user", "content": tool_results})

        # max steps reached
        return AgentResult(
            output={}, status="failed",
            steps_used=steps, tokens_used=total_tokens,
            error=f"max steps ({self.max_steps}) reached"
        )

    async def _call_tool(self, name: str, args: dict) -> dict:
        """Route tool call through tool registry (next post)."""
        from tools.registry import registry
        return await registry.call(name, args, agent=self.name)

    def _build_task_prompt(self, task: str, memory: str) -> str:
        parts = [f"Task: {task}"]
        if memory:
            parts.insert(0, f"Relevant past context:\n{memory}\n")
        return "\n\n".join(parts)

# agents/research.py
from agents.base import BaseAgent

class ResearchAgent(BaseAgent):
    name      = "research_agent"
    model     = "claude-haiku-4-5"   # fast for search tasks
    max_steps = 8

    def system_prompt(self) -> str:
        return """
You are a research agent specializing in ML paper discovery.
Your job: find papers, extract claims, identify gaps.
You are NOT a general assistant. Stay in scope.

For each paper return exactly:
- title: full paper title
- claim: one sentence, what it argues
- method: one sentence, how they tested it
- relevance: one sentence, why it matters for this query

When you have enough papers, return JSON:
{
  "papers": [...],
  "gap_identified": "what has NOT been tested",
  "suggested_next_query": "what to search for next"
}
No preamble. Valid JSON only.
"""

    def tools(self) -> list[dict]:
        return [
            {
                "name": "search_arxiv",
                "description": "Search arXiv for papers on a topic",
                "input_schema": {
                    "type": "object",
                    "properties": {
                        "query": {"type": "string"},
                        "max_results": {"type": "integer", "default": 10},
                    },
                    "required": ["query"]
                }
            },
            {
                "name": "search_semantic_scholar",
                "description": "Search Semantic Scholar, good for citation data",
                "input_schema": {
                    "type": "object",
                    "properties": {
                        "query": {"type": "string"},
                        "year_from": {"type": "integer"},
                    },
                    "required": ["query"]
                }
            },
        ]
কখন একটা Agent, কখন Multiple
1
Simple single-step task: একটা agent-ই যথেষ্ট। "arXiv-এ GRPO search করো।" Research agent একা handle করতে পারবে। Orchestrator overhead justify করে না।
2
Multi-domain task: একাধিক agent দরকার। "Paper খোঁজো, code implement করো, result analyze করো।" তিনটা আলাদা skill, তিনটা agent।
3
Parallel independent subtasks: একই agent-এর multiple instances। তিনটা আলাদা topic একসাথে search করতে হবে। তিনটা research agent parallel-এ চলবে।
4
Quality check দরকার: দুইটা agent same task করে, output compare করো। Agreement থাকলে confident। না থাকলে flag করো। High-stakes task-এ useful।
Over-engineering trap
শুরুতে সব কিছুর জন্য আলাদা agent বানানোর দরকার নেই। একটা research agent দিয়ে শুরু করো। প্রয়োজনে split করো। Agent বাড়ানো সহজ, কিন্তু tangled agent system debug করা nightmare।
Sub-agent design-এ সবচেয়ে important সিদ্ধান্ত হলো scope। কতটুকু করবে, কতটুকু করবে না। Scope ছোট রাখো। Quality বাড়বে। Tool list ছোট রাখো। Hallucination কমবে।

পরের post-এ দেখবো Tool Registry: কেন agents directly tool call করে না, permission model কীভাবে কাজ করে, আর audit trail কেন production-এ critical। এটাই series-এর শেষ major component।
