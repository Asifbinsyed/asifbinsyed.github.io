Observability Layer: Production-এ অন্ধকারে কাজ করা যায় না

System deploy করলেই কাজ শেষ না। আসল কাজ শুরু হয় তারপর। কী হচ্ছে জানতে হবে, কোথায় ধীর হচ্ছে দেখতে হবে, কিছু break করার আগেই বুঝতে হবে। Observability ছাড়া এটা সম্ভব না।

A
Asif Bin Syed ML Researcher · OMSCS @ Georgia Tech · May 2026

রাত ৩টা। তোমার phone-এ notification আসলো: "API error rate 40%।" তুমি laptop খুলে dashboard দেখলে। কিছুই বুঝলে না কারণ কোনো dashboard নেই। Log দেখলে। লক্ষ লক্ষ line। কোথায় problem? জানো না। এটাই হয় observability না থাকলে।

Observability মানে শুধু logging না। তিনটা জিনিস একসাথে: Metrics (কী হচ্ছে সংখ্যায়), Traces (কোথায় কতক্ষণ লাগছে), আর Logs (ঠিক কী ঘটেছে)। এই তিনটাকে একসাথে বলে observability-র তিন স্তম্ভ।

Metrics

সংখ্যায় স্বাস্থ্য

Latency, error rate, throughput। Time-series data। Dashboard-এ দেখা যায়। Alert trigger করে।

Traces

Request-এর যাত্রা

একটা request কোথায় কতক্ষণ কাটালো। Gateway থেকে agent থেকে tool পর্যন্ত পুরো path।

Logs

ঘটনার রেকর্ড

কী ঘটেছে exactly। Error stack trace, input/output, context। Debug-এর সময় দরকার।

পুরো Architecture

Agentic system-এ observability একটু বেশি complex কারণ request একটা না, অনেকগুলো component-এর মধ্যে ঘুরে। Gateway, orchestrator, sub-agent, tool registry, সব জায়গায় কী হচ্ছে সেটা একসাথে দেখতে হবে।

শুধু metrics থাকলে জানবে "error rate বেড়েছে।" কিন্তু কোথায়? জানবে না। Trace যোগ করলে জানবে "orchestrator-এ slow।" কিন্তু কেন? জানবে না। Log যোগ করলে জানবে "OpenAI API timeout, model overloaded।" তখন fix করতে পারবে।

Signal প্রশ্নের উত্তর দেয় Tool
Metrics "কী" হচ্ছে? Error rate কত? Latency কত? Prometheus
Traces "কোথায়" হচ্ছে? কোন component slow? Jaeger বা Tempo
Logs "কেন" হচ্ছে? ঠিক কোন error, কোন input? Loki বা Elasticsearch
LLM-specific কোন prompt কত cost করলো? কোন model fail করলো? Langfuse বা Arize Phoenix
Distributed Tracing: Agentic System-এ সবচেয়ে জরুরি

Normal web app-এ tracing comparatively simple। Request আসে, DB query হয়, response যায়। কিন্তু agentic system-এ একটা request হয়তো orchestrator call করে, orchestrator তিনটা sub-agent parallel-এ চালায়, প্রতিটা agent দুইটা করে tool call করে। মোট ৭টা component। সবার timing একসাথে দেখতে হবে।

এই waterfall দেখলেই বুঝতে পারবে কোথায় ২ সেকেন্ড যাচ্ছে। Web search tool slow। হয়তো rate limit, হয়তো network, হয়তো external API-র সমস্যা। Log দেখলে exact কারণ পাবে।

Implementation: OpenTelemetry দিয়ে

OpenTelemetry একটা vendor-neutral standard। একবার instrument করলে Jaeger, Tempo, Datadog, যেকোনো backend-এ পাঠাতে পারবে। Agentic system-এ প্রতিটা component-এ span create করতে হবে।

observability.py · OpenTelemetry instrumentation 
# observability/tracer.py
from opentelemetry import trace, metrics
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.metrics import MeterProvider
import time, logging, structlog

# --- Setup tracer ---
provider = TracerProvider()
provider.add_span_processor(
    BatchSpanProcessor(OTLPSpanExporter(endpoint="http://otel-collector:4317"))
)
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("agentic-system")

# --- Setup metrics ---
meter = metrics.get_meter("agentic-system")

llm_latency = meter.create_histogram(
    name="llm.request.duration",
    description="LLM call duration in seconds",
    unit="s",
)
agent_calls = meter.create_counter(
    name="agent.calls.total",
    description="Total sub-agent invocations",
)
token_cost = meter.create_counter(
    name="llm.tokens.total",
    description="Cumulative tokens used",
)

# --- Structured logger ---
log = structlog.get_logger()

# --- Decorator for any agent function ---
def observe(agent_name: str):
    def decorator(func):
        async def wrapper(*args, **kwargs):
            with tracer.start_as_current_span(agent_name) as span:
                start = time.time()
                span.set_attribute("agent.name", agent_name)
                try:
                    result = await func(*args, **kwargs)
                    span.set_attribute("agent.status", "success")
                    agent_calls.add(1, {"agent": agent_name, "status": "ok"})
                    return result
                except Exception as e:
                    span.record_exception(e)
                    span.set_attribute("agent.status", "error")
                    agent_calls.add(1, {"agent": agent_name, "status": "error"})
                    log.error("agent_failed", agent=agent_name, error=str(e))
                    raise
                finally:
                    duration = time.time() - start
                    llm_latency.record(duration, {"agent": agent_name})
        return wrapper
    return decorator

# Usage: decorate any agent
@observe("research_agent")
async def research_agent(query: str) -> str:
    # your agent logic here
    ...
LLM-specific Observability: Langfuse

General observability tool-গুলো LLM-এর জন্য পুরোপুরি যথেষ্ট না। কারণ LLM-এ কিছু specific জিনিস track করতে হয়: prompt কী ছিল, response কী আসলো, কত token গেলো, cost কত হলো, আর কোন model call হলো। Langfuse এই কাজটা করে।

Production reality
তোমার system-এ হঠাৎ cost ৩ গুণ বাড়লো। General metrics-এ দেখবে "token usage বেড়েছে।" কিন্তু কোন feature, কোন agent, কোন prompt? Langfuse ছাড়া বলা impossible। Langfuse দিয়ে ঠিক কোন call-টা expensive সেটা second-এর মধ্যে বের করতে পারবে।
Alert Rules: কোনগুলো থাকা দরকার
1
Error rate > 5% for 5 minutes. যেকোনো agent বা component-এ। Immediately page করো। Users impact হচ্ছে।
2
P99 latency > 10 seconds. 99th percentile user-দের ১০ সেকেন্ডের বেশি wait করাচ্ছে। Acceptable না।
3
LLM cost > $50/hour. Budget circuit breaker। Runaway loop বা abuse detect করতে।
4
Agent timeout rate > 10%. কোনো tool বা external API ধীর হয়েছে। Fallback trigger করার signal।
5
Guardrail block rate sudden spike. হয়তো prompt injection attack। হয়তো model behavior change। দুইটাই urgent।
Common mistake
অনেকেই শুধু error alert রাখে। Latency alert রাখে না। User যখন ৩০ সেকেন্ড wait করছে, error নেই কিন্তু experience terrible। Latency SLO set করো, alert রাখো।
Observability হলো তোমার system-এর কাছে প্রশ্ন করার ক্ষমতা। "কী হচ্ছে?" জানো। "কোথায়?" জানো। "কেন?" জানো। এই তিনটা ছাড়া production engineering করা মানে অন্ধকারে হাঁটা।
