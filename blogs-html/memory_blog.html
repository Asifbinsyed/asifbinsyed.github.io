Memory + Vector Store: Agent কীভাবে মনে রাখে

এই series-এর শুরুতে একটা interview question ছিল: "Memory কোথায় থাকবে?" সেই প্রশ্নের পুরো উত্তর এই post-এ। Memory কী, কত ধরনের, vector store কীভাবে কাজ করে, আর সেই trade-off কোনটা কখন choose করবে।

তুমি একজন researcher-কে জিজ্ঞেস করলে: "তিন মাস আগে তুমি PRM নিয়ে কী পড়েছিলে?" সে মনে করতে পারবে কারণ human memory persistent। কিন্তু একটা LLM agent-কে জিজ্ঞেস করলে? প্রতিটা conversation fresh start। Memory layer এই সমস্যা solve করে।

Agent-এর memory না থাকলে প্রতিটা request-এ সব কিছু আবার explain করতে হয়। "তুমি কে, কী করছো, আগে কী হয়েছে।" এটা annoying, expensive, আর unscalable। Memory layer agent-কে context দেয় যাতে সে জানে কোথায় আছে, আগে কী হয়েছে, কী relevant।

Memory ছাড়া agent হলো goldfish। প্রতি ৩ সেকেন্ডে ভুলে যায়। Memory দিলে সে researcher হয়। Past experiment মনে রাখে, pattern দেখে, build করে।
Memory চার ধরনের

Human memory-র মতো agent memory-ও এক রকম না। চারটা আলাদা type, চারটার কাজ আলাদা।

Short-term memory

Current conversation-এর context। LLM-এর context window-এ থাকে। Session শেষ হলে চলে যায়। Fast কিন্তু ephemeral।

Long-term memory

Persistent store। Database বা vector store-এ থাকে। Session-এর পরেও survive করে। User preferences, past decisions।

Episodic memory

"কখন কী হয়েছিল।" Specific events, experiments, outcomes। Timeline-based। "Last Tuesday-র search result।"

Semantic memory

Facts এবং concepts। "PRM মানে কী।" "GSM8K কোন benchmark।" Knowledge base। Structured বা vector-indexed।

পুরো Architecture

Memory layer orchestrator আর agents-এর মাঝখানে বসে। Orchestrator context request করে। Memory layer সঠিক information retrieve করে। Agent সেটা নিয়ে কাজ করে। আর agent-এর output আবার memory-তে store হয়।

Vector Store: Embedding কীভাবে কাজ করে

Vector store-এর core idea হলো: text-কে number-এ convert করো। Similar text থেকে similar numbers আসে। তারপর "এই text-এর কাছাকাছি কী আছে?" খুঁজলে number-এর distance দিয়ে বের করা যায়। এটাই semantic search।

"What is the capital of France?" আর "France-এর রাজধানী কী?" দুইটা different string। Exact match হবে না। কিন্তু embedding space-এ দুইটা প্রায় একই জায়গায় থাকবে। কারণ meaning একই।

Text to vector: embedding model converts meaning to numbers

The Trade-off: Centralised vs Distributed

এই series-এর শুরুতে interview-এর প্রশ্ন ছিল এটা। এখন পুরো context বোঝার পর সঠিক উত্তর দেওয়া যাবে।

Centralised memory (Orchestrator-এ)

Consistencyসব agent same view
Latencyএকটু বেশি, central hop
Sync neededনা, single source
Debuggingসহজ, এক জায়গায়
Best formulti-step tasks

Distributed memory (Sub-agent-এ)

Consistencyagents diverge করতে পারে
Latencyকম, local access
Sync neededহ্যাঁ, complex
Debuggingকঠিন, scattered state
Best forparallel independent tasks
Interview answer
"Centralised memory choose করলাম কারণ আমার task-গুলো sequential এবং dependent। Research agent-এর output analysis agent ব্যবহার করে। Consistency critical। Speed secondary। Distributed memory তখন বেছে নিতাম যদি agents সম্পূর্ণ independent parallel task করতো।"

এটাই সঠিক উত্তর। Not "centralised is better।" Rather: "এই context-এ centralised কারণ..."
Implementation: ChromaDB দিয়ে

Toy project আর research harness দুইটার জন্যই ChromaDB সবচেয়ে easy starting point। Local-এ চলে, no server needed, Python-এ simple API।

memory.py · ChromaDB vector store implementation 
# memory/vector_store.py
import chromadb
from chromadb.utils import embedding_functions
from dataclasses import dataclass
from datetime import datetime
import uuid

@dataclass
class MemoryEntry:
    content:   str
    source:    str           # "research_agent", "user", "run_x7k2"
    tags:      list[str]
    timestamp: str = None

    def __post_init__(self):
        if not self.timestamp:
            self.timestamp = datetime.now().isoformat()


class ResearchMemory:
    def __init__(self, persist_dir: str = "./memory_store"):
        self.client = chromadb.PersistentClient(path=persist_dir)
        self.ef = embedding_functions.SentenceTransformerEmbeddingFunction(
            model_name="all-MiniLM-L6-v2"  # free, local, fast
        )
        self.collection = self.client.get_or_create_collection(
            name="research_memory",
            embedding_function=self.ef,
            metadata={"hnsw:space": "cosine"}
        )

    def store(self, entry: MemoryEntry) -> str:
        """Store a memory entry, return its ID."""
        mem_id = str(uuid.uuid4())
        self.collection.add(
            ids=[mem_id],
            documents=[entry.content],
            metadatas=[{
                "source":    entry.source,
                "tags":      ",".join(entry.tags),
                "timestamp": entry.timestamp,
            }]
        )
        return mem_id

    def retrieve(self, query: str,
                   n: int = 5,
                   threshold: float = 0.7,
                   tags: list[str] = None) -> list[dict]:
        """Semantic search. Returns relevant memories above threshold."""
        where = None
        if tags:
            # filter by tag if specified
            where = {"tags": {"$contains": tags[0]}}

        results = self.collection.query(
            query_texts=[query],
            n_results=n,
            where=where,
        )

        memories = []
        for i, doc in enumerate(results["documents"][0]):
            score = 1 - results["distances"][0][i]  # cosine: 1=identical
            if score >= threshold:
                memories.append({
                    "content":   doc,
                    "score":     round(score, 3),
                    "metadata":  results["metadatas"][0][i],
                })

        return sorted(memories, key=lambda x: x["score"], reverse=True)

    def store_run(self, run_id: str, query: str,
                    papers: list, summaries: list):
        """Store a full digest run in memory for future retrieval."""
        # store the query itself
        self.store(MemoryEntry(
            content=f"Research query: {query}",
            source=run_id, tags=["query"]
        ))
        # store each paper summary
        for paper, summary in zip(papers, summaries):
            self.store(MemoryEntry(
                content=f"{paper.title}: {summary}",
                source=run_id,
                tags=["paper", "summary"]
            ))


# --- Usage in digest pipeline ---
memory = ResearchMemory()

# before searching: did we look at this before?
past = memory.retrieve(
    query="PRM vs ORM generalization",
    threshold=0.85,       # high threshold: only very similar
    tags=["query"]
)
if past:
    print(f"Similar query run before: {past[0]['metadata']['source']}")

# after run: store results
memory.store_run(run_id, query, papers, summaries)
Memory কীভাবে Agent-এর Prompt-এ যায়
1
Task আসে orchestrator-এ। "PRM paper-এর related work লেখো।"
2
Memory controller query করে। "এই topic-এ আগে কী search করেছি? কী পেয়েছিলাম?" Vector store থেকে top 3-5 relevant memories retrieve করে।
3
Context builder assemble করে। Retrieved memories + current task + agent instruction একসাথে। Token budget মেনে।
4
Agent prompt পায়। "Task: ... / Relevant past context: ... / Previous findings: ..." Agent informed হয়ে কাজ শুরু করে।
5
Output memory-তে store হয়। পরের request-এ এই output relevant হলে automatically retrieve হবে।
Token budget সাবধান
Memory retrieve করা ভালো। কিন্তু সব কিছু prompt-এ দিলে context overflow। GPT-4o-র 128k context বড় মনে হয় কিন্তু 50টা paper summary দিলে সহজেই ভরে যায়। Memory controller-এর কাজ হলো most relevant-টা বেছে নেওয়া, সব দেওয়া না।
Memory system ভালো হলে agent-এর output ভালো হয়। আর agent-এর output ভালো হলে memory আরো সমৃদ্ধ হয়। এটা একটা flywheel। প্রথম কয়েকটা run-এ slow, কিন্তু সময়ের সাথে system আরো intelligent হয়।
